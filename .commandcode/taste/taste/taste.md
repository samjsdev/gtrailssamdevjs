# Taste
- Keep running progress tracked in a repo-level `planandprogress.md` file that is kept up to date during long tasks, so work can be resumed after a crashed/interrupted request instead of rediscovering state each time. Confidence: 0.9
- Tackle multi-item fix lists strictly one-by-one: fully complete and verify each item (e.g., each website template) before moving on to the next, instead of batching changes across items. Confidence: 0.9
- Verify frontend changes end-to-end before considering work done: run `npx tsc --noEmit`, start the dev server, curl every route for HTTP 200, grep the rendered HTML for leftover/unwanted strings, and confirm interactivity with Playwright — element screenshots plus scripted clicks (e.g., selecting calculator options) to prove state updates live — then stop the dev server and free the port. Confidence: 0.9
- When adapting templates/copied code to a new theme, sweep every fallback copy, image reference, gallery category, alt text, and placeholder for remnants from the old theme/domain (e.g., interior-design wording left in an architecture template, wrong-profession form placeholders). Leftover remnants are explicitly unacceptable. Confidence: 0.9
- Interactive UI components (calculators, lead forms) must be cleanly designed and easy to understand — cramped grids, opaque pricing logic, truncated labels are treated as "very bad" and warrant a full redesign, not a patch. Confidence: 0.8
- Shared multi-template components (estimators, calculators) must be restyled to each template's own design language — fonts, accent colors, card shapes — not shipped with another template's theme tokens (e.g., t11 brown focus colors inside the green t12 theme are wrong); also ensure such components are actually imported and rendered, replacing any generic placeholder form left in their section. Confidence: 0.8
- Before "fixing" a suspicious string on a rendered page, trace its provenance: client-provided data (e.g., `data/<client>/source.json` fields that legitimately override template fallbacks) is intentional; only template-level fallback copy, images, identifiers (const names like ROOM_SPOTLIGHTS), and image filenames count as remnants. Confidence: 0.9
- When fully replacing a file via write, first back up the original to `$COMMANDCODE_SCRATCHPAD`, and for paths with special characters like `[slug]` that trip file-tool globs, prefer shell copy (cp/head/truncate) over in-place editor writes to avoid botched merges. Confidence: 0.7
- For before/after image-comparison sections, avoid static two-column layouts; build a full-width comparison slider that auto-animates on load — handle starting at far right displaying the "before" state, then sliding left to reveal the "after" — matching any provided reference screenshots (e.g., under `public/ss/reference screenshots`). Confidence: 0.8
- When a design pattern or fix is accepted on some parallel website templates, treat it as canonical and propagate it to every sibling template that still has the old/equivalent section (e.g., slider redesign implemented in templates 11/12/14 must also land in 13 and 17), keeping each template's own theme tokens. Confidence: 0.8
